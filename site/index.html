claude code skill · ux-design-max

Four agents. One pipeline. No agent reviewing its own work.

UX Design Max splits feature work in Claude Code into research, design, build, and review — four subagents, each on the model its job actually needs, with an explicit handoff between every stage and a defined escalation path for when a fix won't stick.

01 / why

Why split the work at all

A single agent doing research, design, implementation, and review in one pass blurs the boundaries between them. It starts coding before the design is settled, and it reviews its own work with the same blind spots that produced it.

Handoffs become explicit

Research hands facts to design. Design hands a spec to build. Build hands a diff to review. Nothing crosses a boundary as an assumption.

The reviewer didn't write the code

An agent grading its own output carries the blind spots that created it. A separate reviewer, on a separate model, with no write tools, doesn't.

Each stage pays for what it needs

Haiku for read-only lookups, Sonnet for execution, Opus where a wrong call is expensive to undo. No premium-model bill for routine research.

02 / pipeline

The pipeline

Each stage's real output is the next stage's input. Don't fill the gaps in between — that boundary is the whole point.

  1. research-agent haiku

    findings + file paths →

  2. design-agent opus

    spec + trade-off →

  3. build-agent sonnet

    diff + what was verified →

  4. code-reviewer-agent opus

    verdict + findings

research-agent

haiku

Reads the codebase and the surrounding context, and cites exactly where its findings come from.

Tools

ReadGrepGlobBashWebFetchWebSearch

Never Edits files, or makes a design decision.

design-agent

opus

Turns research into a concrete spec, and names the one trade-off it made to get there.

Tools

ReadGrepGlobBash

Never Writes implementation code — it has no Edit or Write tool, deliberately.

build-agent

sonnet

Implements exactly the spec it was handed, and verifies its own work before handing off a diff.

Tools

ReadGrepGlobBashEditWrite

Never Expands scope, or attempts a third fix.

code-reviewer-agent

opus

Checks spec match, plus correctness, security, and maintainability, with no ability to touch the code itself.

Tools

ReadGrepGlobBash

Never Edits files — it diagnoses and recommends only.

03 / escalation

When the builder gets stuck

Most agent loops fail the same way — attempt, fail, attempt again, fail again, then attempt a third time with more confidence and less information. build-agent is capped at two.

  1. Fix attempt 1

    Fails.

  2. Fix attempt 2, same issue

    Fails.

  3. Stop.

    build-agent does not try a third time.

  4. Hand off to code-reviewer-agent

    With:

    • the original design/spec
    • the bug as observed
    • both failed attempts, and why each one didn't work

  5. Fresh diagnosis

    The reviewer is required not to repeat either failed attempt. The usual finding is that both attempts touched a code path that isn't the one driving the bug — a display-layer fix for a validation bug, say. It returns one specific, different, concrete fix, or states plainly that it can't resolve it and why.

Tested end-to-end in this repo

A deliberately introduced off-by-one bug, paired with two fabricated failed-fix narratives, was correctly diagnosed by code-reviewer-agent on the first pass — including a clear explanation of why each fake attempt could never have worked.

04 / caveat

Where this gets it wrong

code-reviewer-agent is thorough but not infallible. In testing it correctly diagnosed the escalated bug above — and separately flagged an already-fixed issue as still broken.

Treat its findings as strong signal, not a verdict. Verify a finding against the actual code before acting on it, and especially before deciding not to ship something it flagged. A false "still broken" is the failure mode to watch for.

05 / install

Install

Into a project

git clone https://github.com/wilkowskij/UX_Design_Max.git
mkdir -p your-project/.claude/agents
cp UX_Design_Max/.claude/agents/*.md your-project/.claude/agents/

Project scope commits alongside your repo. Use ~/.claude/agents/ instead to make the pipeline available in every project.

Before you rely on it

Name collisions are real

code-reviewer-agent is a name other skills also use (smart-model-router, for one). If the destination already has one, merge the roles deliberately or keep both under distinct names. Don't overwrite silently.

Registry timing, not a bad file

A freshly written agent file may not be visible to the Task/Agent tool until the session's agent registry refreshes. An immediate agent type not found is a timing issue; retry next turn or in a fresh session.

Smoke-test each agent alone first

  • research-agent -> a factual question about the codebase; it should cite a real file and edit nothing.
  • design-agent -> a small design ask; it should state an explicit trade-off, not just a plan.
  • build-agent -> a one-line design; it should implement exactly that and nothing more.
  • code-reviewer-agent -> an obviously buggy stub; it should state the bug plainly rather than hedge.
